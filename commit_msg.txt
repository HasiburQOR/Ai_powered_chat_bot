Fix widget template-comment leak; multilingual replies; travel-lead profiles

Widget bug (live): the multi-line `{# #}` comment in bubbles.html leaked
into the chat as literal text — Django `{# #}` comments cannot span
multiple lines. It now uses `{% comment %}`, and the fragment renders
every bot bubble of the turn (regression-tested).

Bot engine:
- Always instructs the LLM to mirror the visitor's language (Hindi gets
  Hindi, etc., English only as fallback) and to keep replies short
  plain-text (no Markdown tables/bold) — widget and IG/Messenger alike.
- handle_inbound_message now returns every outbound Message of the turn;
  the platform webhook and the widget fragment deliver all of them.
- Optional scripted travel-profile question after the first reply,
  controlled by BotSettings.profile_collection_enabled and
  profile_intro_message (editable in Dashboard > Settings).

Travel-lead profiles (new `profiles` app):
- TravelProfile (1:1 Customer) with BP-xxxxxx numbers minted under a
  row lock; completeness flag + missing-field reporting; captured
  fields feed back into the bot's LLM context.
- Celery task extracts details from every visitor message via the
  active LLM (strict-JSON prompt, fuzzy dates, never guesses).
- Dashboard > Profiles: searchable/filterable list, per-profile detail
  with staff editing, CSV + Excel (openpyxl) exports, and PNG downloads
  (profile card + chat transcript image via Pillow; DejaVu fonts added
  to the image; filenames <ProfileNumber>_<Name>.png).

Tests: 60/60 (fragment leak regression, extraction + numbering, engine
intro + language instructions, dashboard exports/PNGs/auth).
